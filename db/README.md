# Database

PostgreSQL migrations are applied in numeric order from `migrations/` by `scripts/run-migrations.py`.

## Migration rules

- Filenames use `NNN_lowercase_name.sql`; versions must be unique.
- A migration must not be empty.
- `schema_migrations` records the version, name, SHA-256 checksum, and application time.
- An applied migration must never be edited, renamed, removed, or reordered. Add a new migration instead.
- The one exception is a recorded `011_password_reset_tokens` migration from the earlier numbering collision. The runner accepts it only when its checksum exactly matches `015_password_reset_tokens.sql` and the reset table exists, moves its tracking entry to version 015, then applies any missing version 011 run-budget migration. Other mismatches still stop migration.
- A PostgreSQL advisory lock prevents two deploys from migrating concurrently.
- Each migration and its tracking row are committed in the same transaction.

The migration chain currently covers extensions/enums, normalized tables, constraints/indexes, monthly run partitions, immutable/audit triggers, concurrency-sensitive functions, views, materialized aggregates, roles/grants, and baseline model pricing.

## Seeds and reset

Seed files live in `seeds/`, use numeric prefixes, and are idempotent. `001_development.sql` creates five baseline development identities; `002_demo.sql` creates a project, membership, prompt/version, and budget; `003_auth_test_users.sql` creates two active users and an admin for local login checks. Passwords in the seed files are Argon2id hashes generated by `api.app.security.hash_password`. Compose passes `--only-development` so startup skips seeds outside development. The direct `scripts/seed-database.py` command accepts only `ENVIRONMENT=development` or `test`; it refuses production and other environments before connecting to PostgreSQL. The development reset recreates the `public` schema, migrates, and seeds in one outer transaction:

```bash
python3 scripts/reset-development.py --confirm-reset
```

Reset refuses any `ENVIRONMENT` other than `development` and refuses to run without explicit confirmation. Use `--database-url` only when the target has been independently verified.
